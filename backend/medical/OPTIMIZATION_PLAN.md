# 医疗 RAG 优化执行计划

更新时间：2026-09-22。范围为本机研究版本；本轮暂不建设医疗人员审核流程。

## 目标与原则

1. 每个健康问题都由统一 Medical Health Agent 和统一 LLM 处理。
2. 检索命中时，关键医学事实优先来自可追溯资料；未命中时仍给保守的一般安全引导。
3. 优先降低错误资料和无来源断言，再扩充覆盖，最后优化速度。
4. 用户界面保持自然语言；证据编号、检索分数和内部状态由后端保存，不要求用户理解 RAG。
5. 健康问题原文不写入检索运行日志；缓存只保存不可逆查询摘要。

## P0：回答与证据闭环

状态：已完成并通过单元测试。

- 从 `medical_search` 工具输出中确定性提取 `knowledge_status` 和来源，不依赖 LLM 自己复制链接。
- 将来源写入最终 WebSocket 响应和消息元数据，前端继续使用现有来源卡片展示。
- 命中、未覆盖、工具不可用三种状态贯穿到最终回答。
- Medical Agent 提示词区分“检索资料事实”和“通用安全引导”，禁止把模型推测伪装成资料结论。
- 增加工具输出解析、来源去重和消息持久化测试。

验收：健康回答即使正文不主动输出链接，最终消息仍带正确来源；未命中不出现虚假来源。

## P1：独立验证与知识覆盖

状态：已完成当前本机阶段。新增 33 道冻结回归题和 10 个高频主题；真正外部盲测仍列入 P4。

- 冻结一份不参与当前门槛调整的 validation v1，覆盖错别字、否定、混合意图、长描述、多轮代词、药名和相似症状。
- validation 结果与开发集分开报告，不因单题失败立即调门槛。
- 在现有固定版本 MedlinePlus XML 中扩充一批高频症状主题，复用来源哈希、版本和过期治理。
- 每次扩充后重建索引，同时运行开发集和 validation 集。

验收：新增主题能召回；原 111 题 Recall@5、错误文档率和无答案拒绝率不倒退。

## P2：多轮与切片质量

状态：已完成受限上下文和当前资料切片修复；更复杂的父子章节策略待长文资料扩充时按需引入。

- 为检索查询传入受限的对话摘要：只含用户明确陈述的症状、持续时间、部位、测量值和用药事实。
- 短追问与上一轮主题合并，禁止把上一轮模型推测作为检索事实。
- 为长章节保留相邻上下文或父章节摘要；表格、清单、危险信号不跨边界截断。
- 用专项用例验证否定、时间和主体不会被改写丢失。

## P3：性能与运行稳定性

状态：已完成启动预热、查询摘要缓存和分阶段诊断；模型量化保持为后续可选实验。

- MCP 启动时预热 BGE 和 reranker，消除第一次用户查询加载模型的等待。
- 增加小容量、短 TTL 的进程内检索缓存；键为查询摘要，不保存问题原文。
- 保留候选数、重排数、冷/热耗时、降级状态监控。
- 在不降低 validation 指标的前提下再评估 ONNX/OpenVINO 和 INT8；不先增加部署复杂度。

验收：热查询 P95 不高于当前约 2 秒；相同查询缓存命中低于 100 毫秒；模型故障仍能降级。

## P4：后续工作

- 陈述级 NLI/LLM 验证器及冲突来源处理。
- 真实用户反馈闭环、盲测集和压力测试。
- 医疗人员审核流程由产品进入公开准备阶段时另行建设。
