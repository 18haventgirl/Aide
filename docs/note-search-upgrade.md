# 笔记检索升级：实现与验收

更新：2026-10-01。本轮落实 P0–P2：可复现评测、长笔记切片、本地混合搜索、索引同步和前端状态修复。医疗 RAG 的索引和模型配置不变。笔记重排及医疗回答评测扩展尚未完成，不计入本轮交付。

## 数据与调用链

1. SQLite 的 `notes` 始终是原始内容与权限的依据，不以向量库反向恢复正文。
2. `notes` 插入、修改、删除触发器在同一事务写入 `note_index_jobs`。后台工作线程领取任务，最多自动重试 5 次，失败保留任务与错误类型。
3. 复用已下载的 `BAAI/bge-small-zh-v1.5`（512 维、CPU、batch=4、校验固定权重摘要）。新向量独立存储在 `backend/data/note_index_v1/chroma`，集合 `notes_bge_zh_v1`，不与旧 OpenAI/hash 向量混用。
4. 向量写成功后，发布 SQLite FTS5 分块与 `note_index_state` 版本，再清理旧块。读时重新核对 SQLite 所属用户、标签、状态与内容版本；未同步更新和已删除条目不能通过旧索引返回。
5. 查询经过当前原文精确匹配、jieba 分词的 FTS5/BM25、BGE 语义召回。精确匹配置顶；其余候选按 RRF（k=60）融合，按笔记去重，重新读取完整原文，并附上片段。
6. HTTP 及 Agent 的笔记向量搜索入口均接入同一服务。HTTP 检索在线程池运行，避免 CPU 查询阻塞异步事件循环。

## 切片

- 短正文尽量整段保留；标题作为每块前缀。
- 长正文优先按 Markdown 标题、换行、中文句末分隔。正文窗口约 400 字符，句子边界重叠不超过约 50 字符；最终以真实 tokenizer 检查总长度不超过 480 tokens。
- 标题前缀最多约 100 tokens；完整标题和正文仍在 SQLite。短代码围栏和短管道表格尽量保留完整，超长结构仍需拆分。
- 每块记录用户、笔记、内容摘要版本、原文起止偏移；块 ID 包含策略版本与偏移。测试验证无正文字符遗漏。
- 当前不是完整 Markdown AST 解析器，尚未实现完整标题层级、跨块表头重复等结构增强。

## 响应与故障处理

- 向量查询最多等待 1.2 秒。单进程最多一个向量查询在执行；超时任务不会排出无界队列。冷启动、模型异常、资源忙时仍提供当前 SQLite/FTS 结果。
- 建索引的模型加载要求约 1.5 GiB 可用内存；启动阶段不足时延后加载，不阻断原文关键词搜索。API 与 MCP 目前仍可能各加载一份模型，尚未改为独立共享推理服务。
- 数据库任务租约 300 秒，用于进程异常后的恢复。当前面向本机低并发；没有租约续期，不宣称适用于任意大笔记或高并发生产负载。
- 搜索日志仅记录 dense 状态、候选数、结果数、耗时，不写入查询文本或笔记正文。
- 前端区分原始列表/搜索结果及两种 loading，300ms 防抖，取消旧请求，丢弃过期响应；清除/退出搜索恢复列表。搜索错误单独提示，不伪装成无结果。详情重新请求原文；菜单点击不会打开详情。

## 本机启用与维护

在 `backend/.env` 配置（密钥、原始数据、索引和备份不进入 Git）：

```dotenv
NOTES_LOCAL_SEARCH=true
NOTE_DENSE_SEARCH=true
NOTE_BGE_MAX_DISTANCE=0.55
```

从 `backend` 目录执行：

```powershell
.\.venv\python.exe -m service.services.note_index_admin build
.\.venv\python.exe -m service.services.note_index_admin status
.\.venv\python.exe -m service.services.note_index_admin retry
.\.venv\python.exe -m service.services.note_search_evaluate
.\.venv\python.exe -m unittest tests.test_note_local_search tests.test_medical_grounding tests.test_answer_audit
```

`build`/`retry` 先使用 SQLite backup API 备份到 `backend/data/backups/`。`build` 为补齐缺失任务，不是强制重建全部已有索引。仍有待处理任务时以非零退出码报告未完成。修复模型/磁盘等原因后使用 `retry` 重新开放失败任务。

本机迁移前备份：`backend/data/backups/notes-before-index-20260929-145705-619369.sqlite`。验收时 3 条原始笔记、3 条已索引笔记、3 个块、0 个待处理任务；没有更改用户笔记正文。

降级：保留 `NOTES_LOCAL_SEARCH=true`，设置 `NOTE_DENSE_SEARCH=false` 并重启后端，继续使用当前 SQLite/FTS 搜索。该开关只禁用查询向量召回，后台建索引仍运行。不要直接切回旧远程向量搜索：启用新路径期间旧索引未双写，需先重建才可使用。数据库备份用于灾难恢复，恢复会影响备份之后的其他业务数据，不应为搜索回退直接覆盖整库。

## 验收记录与限制

- 23 项后端测试通过：事务回滚、隔离/过滤、更新/删除、失败后的陈旧结果排除、关键词回退、SQL 通配符、去重、分块覆盖、慢查询上限和租约竞争等，另含医疗相关回归。
- 使用 10 条人工合成笔记（含一条事实位于长正文末尾的笔记）、60 条问题；30 条开发集用于选择阈值、30 条独立保留验证集。阈值在 0.35/0.45/0.55 中按开发集选择 0.55，没有根据验证集反复调参。
- 验证集正例 Recall@5 = 95%（19/20），负例拒绝 = 100%（10/10）；纯原文关键词基线 Recall@5 = 50%。温模型本地服务函数 P95 约 25.6ms，纯关键词基线约 0.32ms，不含 HTTP、冷启动、网络和大规模库负载。
- 已知漏召回：合成问题“去外地办事花的钱怎么申请返还”；页面问题“游览古迹要怎么安排行程”也未召回旅行笔记。保留为后续改进样例，不把合成集指标当作真实用户总体效果。
- 页面已验证关键词搜索、搜索退出恢复 3 条笔记、完整详情及具体自然语言查询。生产构建通过。全项目 TypeScript 检查仍受原有实验文件 `performance.ts`、`useOptimizedScroll.ts`、`main-test.tsx` 的报错影响，本轮未覆盖它们。
- 合成评测产物：`backend/data/note_search_reports/synthetic_v1.json`，本机保留，不提交个人数据。
- 10 月 1 日恢复服务时，3000 被 Mineradio 占用、3001 被 Remotion 占用，因此本次前端使用 `http://127.0.0.1:3002/`；API 为 8000，MCP 为 8002。未关闭这两个外部应用。
