# 前端错误排查与验证记录

验证日期为 2026-11-02，对应 `codex/medical-record-parser` 分支的提交 `a7fb72a`，使用 Node.js 24.19.0。修复前的 ESLint 报告有 121 个错误和 12 个警告。修复后沿用原规则，并将警告也设为检查失败条件。

| 修复前的检查项 | 数量 | 处理方式 |
| --- | ---: | --- |
| 显式使用 `any` | 96 | 根据接口定义笔记、待办、健康记录和会话类型，对聊天消息、引用来源和错误响应先检查结构再读取。 |
| 未使用变量、参数或导入 | 21 | 清理无用代码，落实按钮组件原本声明的 `asChild` 行为。 |
| 组件与辅助函数混合导出 | 3 | 分开 Toast 组件与 Hook，收窄样式辅助函数的导出范围。 |
| 无效果的表达式 | 1 | 明确执行对应操作。 |
| React Hook 依赖警告 | 12 | 修正回调依赖、请求返回顺序和事件订阅的清理。 |

认证是其中能直接影响用户的一处问题。后端刷新接口把新令牌放在 `token`，前端原先按 `data` 读取，定时刷新也只验证旧令牌。现在刷新成功会保存新令牌。仍在有效期内遇到暂时的服务错误会保留登录状态，后台刷新不会卸载当前工作区，退出后才到达的刷新结果也不会恢复旧会话。聊天连接复用同一条正在建立的连接，后端初始化失败时最多自动重试五次。

| 实际执行的检查 | 结果 |
| --- | --- |
| ESLint、TypeScript、生产构建 | 0 个 lint 错误、0 个 lint 警告，类型检查和构建通过。构建仍提示浏览器兼容性数据较旧。 |
| 本地回归 | 22/22 通过。覆盖认证和刷新异常、迟到的请求、引用和 Markdown 静态渲染、WebSocket 重连和监听器清理。 |
| 真实服务联调 | 11/11 通过，无跳过。10 项 HTTP 场景覆盖登录、当前用户、刷新、笔记和标签、待办及统计、健康记录、会话列表、重开已保存病历、空文本 422 和无效令牌 401。另 1 项通过前端代理建立 WebSocket，收到后端分配的连接 ID。 |

联调通过 `127.0.0.1:3010` 访问前端代理，后端使用独立的 SQLite 演示库。聊天检查到收到就绪消息为止。本轮未操作浏览器，也未重新执行模型生成、PDF 或图片上传的完整流程。

从项目根目录复现：

```powershell
cd ui
npm run check
npm run build
```

另行启动本机前端、后端及聊天工具服务后，在同一 `ui/` 目录使用演示账号执行联调。把示例中的 3010 换成启动时实际分配的前端端口。

```powershell
$env:AIDE_SMOKE_BASE_URL = 'http://127.0.0.1:3010'
$env:AIDE_SMOKE_USERNAME = '<演示用户名>'
$env:AIDE_SMOKE_PASSWORD = '<演示密码>'
$env:AIDE_SMOKE_WS = '1'
npm run test:api
```

联调脚本有 11 个子场景，Node 的汇总还计入外层测试，全部通过时显示 `pass 12`。病历详情检查需要该账号至少有一份已保存的演示病历，库为空时这项会明确标为跳过。测试代码见[前端回归](../ui/tests/frontend-regression.test.mjs)和[真实服务联调](../ui/tests/frontend-api-smoke.test.mjs)。
