# 阶段2：输入预算与结构切片

更新：2026-10-16。状态：实现与离线合同测试已完成，真实模型对照待运行；**尚未启用新运行策略**。

## 问题和实现

1. 旧600字符/80字符重叠策略继续保留，用于旧索引与历史复现。256与512的桥接比较均用旧切片、旧输入策略，单独观察长度影响。
2. `token_budget.py` 使用本机真实tokenizer计算长度。候选策略为当前问题最多64 tokens优先、标题最多32 tokens，正文使用句对剩余空间；特殊token计入总预算。长问题保留首尾并标记不完整，旧用户事实只取余量内最近部分。原始完整问题先做范围检查，再施加1000字符传输上限。
3. 新子块长度同时检查重排与embedding两个tokenizer。候选180/220 tokens包含去重后的标题与章节，分别比较256/384句对；不是“正文220再无条件加上问题”。
4. 子块用于向量、BM25及重排。排序并通过原有过滤后，扩展同一父段的完整邻句，回答上下文上限480 tokens；不跨章节/问答边界。扩展不改变用于排序的子块内容。
5. 普通文章按章节和句子组织；`问：/Q:`格式保留问题与回答单元，跨空行保持归属；Markdown表格每行携带原始表头和分隔行。超长原子单元必须拆开时标记`boundary_split`；问句/表头本身放不下时构建失败。当前72篇正文主要是文章结构，问答/表格分支使用合成合同测试验证。
6. 每块记录规范原文字符位置、parent ID/范围、section、配置及tokenizer指纹；返回给LLM的父段与重排子块分别验证原文映射。不会把整篇文章ID命中当作关键句进入模型。
7. 工具与新旧评测共用问题传输裁剪；新评测额外记录实际重排输入范围/长度、可见依据与可见条件。运行日志只保留聚合数，逐块范围只留在内存或本机评测报告中。

“原文范围完整”是字面保留检查，不表示条件适用性和回答医学正确性已经得到验证。

## 预先确定的对照矩阵

| 名称 | 切片 | query策略 | 句对上限 | 配置用途 |
| --- | --- | --- | ---: | --- |
| legacy-256 | 原600字符 | 原策略 | 256 | 同代码基线 |
| bridge-512 | 原600字符 | 原策略 | 512 | 单独判断长度影响 |
| child180-pair256 | 180-token子块/480-token父上下文 | 当前问题优先 | 256 | 较小输入候选 |
| child220-pair384 | 220-token子块/480-token父上下文 | 当前问题优先 | 384 | 较完整句子候选 |

四配置均运行相同的274题：原有258题及新16题输入工程回归。每配置比较hybrid与rerank，真实BGE权重与tokenizer均记录指纹，CPU2线程、embedding batch4、rerank batch1，其他候选和过滤参数固定。新16题是开发者构造且已知来源的回归题，**不属于阶段3独立验证集**。

旧开发题中已移除外文来源的标签保留，逐组报告不可用来源，不能把这些题当作新中文覆盖率。紧急题仅测既有规则；不会算作真实Agent/LLM验收。

资源要求：启动与加载reranker前均检查至少1536 MiB可用内存。不调低门槛、不关闭其他程序。每次失败单独保留，恢复须匹配代码/数据/配置；每配置在独立进程和Chroma临时索引运行。固定顺序耗时仅作描述，正式随机交错性能测试在阶段6。

## 执行入口

从backend目录、代码提交干净后运行：

```powershell
$env:PYTHONIOENCODING='utf-8'
python -m medical.stage2_matrix --directory data/evaluation_reports/stage2_20261016
```

逐配置执行可加`--configuration legacy-256`；续跑同目录加`--resume`，不会覆盖旧失败。实现、语料或题集变化后必须使用新的目录。使用项目现有虚拟环境的Python。

仅tokenizer审计（不加载权重，不调用API）：

```powershell
$env:USE_TORCH='0'
python -m medical.audit_token_chunks --output data/evaluation_reports/token_chunk_audit_new.json
```

`USE_TORCH=0`仅供上述独立审计进程；模型实验须在另一进程中清除它。
