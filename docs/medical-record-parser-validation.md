## 验证环境

- 代码工作区：当前 `codex/medical-record-parser`。
- 使用现有 Python 运行时；OCR 依赖另行安装到本工作区 `logs/parser-ocr-deps`，未安装到主工作区环境。
- OCR 已验证直接依赖：Pillow 11.3.0、RapidOCR ONNX 1.4.4、PDFium 4.30.0。
- 前端依赖来自已有锁文件对应的本地依赖副本。
- 预览使用独立的 `logs/parser-preview.db` 和向量存储目录。正式个人数据库未用于这些检查。
- 合成材料、脚本、截图、模型结果和预览数据库在已忽略的 `logs/` 中，不进入 Git。

## 已修正的实测问题

- PDFium 4.30 的文档对象不支持直接作为上下文管理器，改为 `contextlib.closing`，扫描 PDF 实测通过。
- Dashboard 的动画背景覆盖了普通层级的解析界面，给解析工作区建立独立层级后重新截图检查。
- API 与旧 Agent 会话适配器可能使用不同事件循环，解析容量限制使用线程安全信号量，并增加跨循环验证。

## 尚未覆盖

- 真实脱敏病历的提取质量、复杂多栏排版、倾斜/模糊照片与手写内容。
- 多实例部署、长任务恢复和批量任务队列。
- 预览没有启动完整 MCP 服务，聊天 WebSocket 出现过连接错误；病历 HTTP 工作区独立可用。Agent 调度通过独立的真实 Runner 调用验证，不能据此声称聊天 WebSocket 的完整演示已通过。
- 第一版按前端“核对后确认保存”的设计默认值实现；可根据用户后续反馈调整。
